# Payments setup

Payments is optional and includes authentication. Select `payments` in `disposabl.json`; the server checks this selection before reading credentials or calling Autumn. With it off, the pricing page blocks purchases and no billing credentials are needed. The authenticated Convex Auth user ID is the Autumn customer ID. Never use a client-supplied customer ID or price.

Set the Autumn environment default currency to USD and verify both prices in the provider preview. For a separate Autumn test environment, configure `AUTUMN_SECRET_KEY` and `BILLING_RETURN_URL` on that app's Convex deployment. The latter must be the absolute HTTPS URL of its `/pricing` page (HTTP localhost is allowed for development), without query or fragment. Do not store the secret in the frontend or `disposabl.json`. Set the corresponding live values separately only when ready to launch.

`payments/autumn.config.example` defines the `credits` consumable feature, $5 monthly plan with 500 credits per cycle, and $5 one-off prepaid top-up for 500 credits. Copy it to `autumn.config.ts` in a separate configuration project with `atmn@2.0.218` installed. Preview with `atmn push` before applying to a dedicated Autumn environment. Its lists are complete: a push can delete unlisted plans and features. Review the diff and test repeated top-ups, renewals and cancellation in sandbox before taking payment. The one-off prepaid credits are documented to last forever; subscription credits reset each cycle. Autumn's docs do not establish that subscription credits survive cancellation. Do not promise that they do. The provider balance is authoritative; a redirect alone does not grant credits. This foundation does not implement usage charging.

The app calls Autumn API 2.6.0 `customers.get_or_create`, `billing.attach`, and `billing.open_customer_portal` server-side. Checkout uses fixed server-owned plan IDs and a fixed 500-credit top-up quantity. Return to pricing may precede provider synchronization; use Refresh to read Autumn again. Setup and test Stripe checkout and portal in Autumn before enabling live use.

## Native subscriptions and synchronization

The account screen supports monthly subscriptions and restore through RevenueCat. Use Autumn's managed RevenueCat integration as the sole sync path, with the same authenticated user ID as RevenueCat `appUserID` and Autumn `customer_id`. Request beta access, connect a RevenueCat project and V2 read-only key in Autumn, map store-level subscription products to `credits_monthly`, and configure separate test and live webhooks using Autumn's provided URL and authorization. Block duplicate web/native subscriptions based on the provider customer state. Mobile purchases use RevenueCat, never Autumn attach. Await Autumn webhook synchronization before treating the Autumn balance as available.

Set public build-time variables `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` and `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY`, plus `EXPO_PUBLIC_REVENUECAT_IOS_MONTHLY_PRODUCT` and `EXPO_PUBLIC_REVENUECAT_ANDROID_MONTHLY_PRODUCT` to the exact store product identifiers. Configure each as a $5 monthly product with no unverified offers. The app displays the store's localized price. Build a new native binary after adding the SDK; Expo Go is insufficient. Android uses `singleTop` when payments is selected so external bank verification can return to the purchase.

Only set backend `REVENUECAT_SYNC_ENABLED=true` after configuring and verifying the matching Autumn environment's managed integration. Without it, the app still reads shared credits but does not offer native purchases. Payments disabled means no billing component or SDK initialization. The SDK uses custom user IDs only and serializes account switching with purchase operations. Sign-out clears UI ownership without creating a RevenueCat anonymous ID. Configure RevenueCat restore behavior deliberately so a restore does not transfer another account's purchases unexpectedly.

Web checkout and native purchasing reject an existing or scheduled monthly plan, and native purchasing also checks RevenueCat's active subscriptions. Unknown provider state blocks a new subscription. These checks reduce duplicate purchases but do not constitute a distributed transaction across concurrent web and store checkouts. Credits always come from Autumn; a store receipt is shown as awaiting synchronization, never added locally.

Autumn's integration documentation does not confirm repeatable consumable top-up grants or their behavior on refund, cancellation, and retries. Do not map or offer native top-ups until Autumn confirms these semantics and sandbox tests demonstrate them. Do not add a custom RevenueCat webhook or another grant path alongside managed sync. Store product IDs, prices, and mappings must be chosen and verified in each store; the web price is not proof of native store pricing.

## Platform connection and starter packaging

Autumn's Platform API is private preview; its documented OAuth connects Stripe to a managed Autumn organization, not an existing Autumn account to Disposabl. Disposabl Connections accepts an encrypted sandbox key and an optional live key. It verifies each through the read-only `plans.list` endpoint. Payments selection requires this connection; other apps remain unblocked. Generator setup installs the sandbox key only on the named development backend, and the live key only on production when supplied. The platform billing key is never copied. Setup initializes `BILLING_RETURN_URL` only when absent, using that deployment's `/pricing` page; change it to your verified custom web origin if needed. Plan catalogs are not changed automatically. Configure and test both plans in each Autumn environment. Disconnecting or omitting a live key does not revoke credentials previously installed on an app; rotate those in Autumn and update each app explicitly.

The parent `reset.ts` removes backend functions before copying `starter/backend`; this patch adds the thin billing wrapper to both places and declares the optional variables in both Convex configs. Preserve the `autumn/` config and kit files when packaging, and regenerate the generated API types after backend functions change. Do not copy any parent credentials.

Native SDK is pinned to `react-native-purchases` 10.16.0 because its required `PurchasesHybridCommon` 19.17.0 is published in CocoaPods. At verification on 2026-11-07, npm 11.0.1 required 20.4.0, which was absent from the CocoaPods specs repository. Upgrade only after both native dependency graphs resolve and installed builds pass.
