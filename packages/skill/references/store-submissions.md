# App Store and Google Play submissions

Use this workflow when the user requests store submission or release. Follow their chosen platforms, accounts, distribution timing, and build constraints. Prior authorization to submit or release remains effective; ask only for information, access, or a decision that is actually missing, or when a tool or legal boundary requires it.

## Match the existing app

Identify the exact App Store Connect (ASC) app record and Apple ID, bundle ID, team, and current release; identify the Play Console app record, package name, track, version code, and signing configuration. Reuse the existing listing when the identifiers and ownership match. Do not infer identity from the display name or an Expo project. If no matching record exists, create a new record only within the requested scope; explain that it is a new listing, not an update or migration of the existing app.

Compare the actual release artifact's identifier, version/build number, signing certificate and entitlements with the store record and authorized team. An ASC bundle ID cannot be changed after a build upload. A Play update needs the same package name, a higher version code, and the correct upload signing key; distinguish the upload certificate from the Play-held app signing certificate. Do not expose private keys or credentials. Stop and report a mismatch instead of uploading to a different listing or replacing signing identity. See [Apple app information](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information/), [Play app updates](https://support.google.com/googleplay/android-developer/answer/9859350), and [Play App Signing](https://support.google.com/googleplay/android-developer/answer/9842756).

## Build, reviewer access, and evidence

Use the user's required build path. When local iOS builds are requested, create a signed device archive with local Xcode and export/upload through the supported App Store Connect path; do not use EAS cloud builds. A simulator build, ad-hoc signature, preview IPA, or keyless payments fixture is not a submission artifact. For Play, build the correctly signed release Android App Bundle (`.aab`); an APK proves neither an AAB upload nor Play delivery. Record source SHA, artifact digest, identifiers, versions, signing evidence, and the target deployment. Verify the release build on an appropriate device, including login, real requested features, saved data after relaunch, and the intended backend. Report any unverified behavior instead of claiming readiness.

If review requires login, provision a dedicated reviewer account for the actual app and review backend using a login method supported by the submitted build and backend. Give it only the permissions and resources needed to exercise the real submitted features; include any required roles, reachable backend, purchase access, and steps. Prepared credentials alone are not an account: register it, then verify login and those features on the submitted build, relaunch, and verify session and data before calling reviewer access ready. Keep credentials out of source, Git, skill files, logs, screenshots, and public chat; enter them only in the store's designated review-access fields via an authorized secure channel. Keep the account and backend usable through review. If Apple requires a subscription flow, follow its current guidance for a review account that can demonstrate it. Explain genuine limits and setup in review notes rather than presenting a mock as a working feature. See [Apple review information](https://developer.apple.com/help/app-review/before-submitting-for-review/complete-review) and [Google review access](https://support.google.com/googleplay/android-developer/answer/15191715).

Use truthful screenshots from the submitted app and supported devices; ensure metadata, privacy policy, age/content ratings, Apple privacy declarations, and Play Data safety reflect the actual app, backend, SDKs, and regional behavior. Do not invent data practices or claim unavailable features. Check [Apple screenshot specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications), [Apple privacy details](https://developer.apple.com/app-store/submitting/), and [Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469).

## Payments and release states

For enabled digital purchases, verify the configured products, prices, store offerings, sandbox transaction, restore and provider synchronization against the intended app and environment. Distinguish local StoreKit configuration, Apple/Google sandbox, provider synchronization, and production fulfillment. A button, mock, or redirect is not proof of payment or credited balance.

For iOS website checkout, verify the actual US StoreKit storefront and purchase eligibility, website option, return flow and authoritative balance refresh. For non-US storefronts retain the applicable native in-app purchase path unless a verified regional entitlement or exception applies. Check the current [Apple review guidelines, section 3.1](https://developer.apple.com/app-store/review/guidelines/) and the app's payment configuration; do not assume a US exception applies worldwide. For Android, follow the current [Google Play payments policy](https://support.google.com/googleplay/android-developer/answer/9858738) and any applicable enrolled regional program; do not treat the iOS policy as Android authorization.

Track each platform separately: artifact built and signed; uploaded; processed and associated with the exact app/version; submitted for review; review outcome; and public or staged release. Upload or TestFlight availability is not App Review submission. Select the store's release mode consistent with the user's instructions and check whether approval triggers automatic publication. Confirm final state in the relevant console and report precise links, identifiers, and blockers. See [Apple submit an app](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app), [Apple release options](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/select-an-app-store-version-release-option), and [Play publishing overview](https://support.google.com/googleplay/android-developer/answer/9859654).
